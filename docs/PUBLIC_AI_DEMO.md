# Public AI demonstration — approval and hosting runbook

Default remains `AI_ACCESS_POLICY=disabled`. This document does not authorise deployment, purchases, credentials or paid calls. Public AI must remain disabled until the owner approves costs/configuration and the actual host passes ingress/storage tests.

## Architecture and quota

One Ubuntu Linux server: NGINX terminates HTTPS, a private loopback signer issues HMAC assertions, Streamlit runs on loopback, and all workers share one local persistent SQLite budget. No external database or extra Python dependency. Never use independent instances, ephemeral storage, NFS/SQLite or a CDN/unverified forwarded-address chain.

NGINX sends its direct TCP peer `$remote_addr` to the internal `auth_request` signer, replaces all incoming X-Demo-* headers and strips Forwarded/X-Forwarded-For/X-Real-IP. The app only accepts the signed assertion under its private signing key and fixed demo ID. It does not use Streamlit's spoofable IP field or arbitrary forwarded headers. Assertions expire after 12 hours; refreshing an old session obtains a new assertion without resetting its quota. Signer remains usable after demo expiry so deterministic analytics can continue; the paid boundary denies an expired demo.

A separate private random key HMACs canonical IPv4/IPv6 addresses. IPv4-mapped IPv6 shares the IPv4 quota. Raw IPs are not stored in the quota DB, portfolio state, chat or application logs. Records remain pseudonymous personal data, not anonymous. Proxy process memory sees raw IPs transiently. Minimal access logs omit IPs, URLs and user payloads; verify proxy error logs/host monitoring do not capture them.

Every nonempty, consented, accepted Ask submission is atomically debited once using `BEGIN IMMEDIATE`, before provider calls. Exactly five across the entire demonstration, without daily reset. A question may perform router + explainer calls; each reserves the existing global request/token budget, and demo contexts allow at most two attempts. Provider failures, timeouts, invalid replies, context rejection or exhausted shared budget after acceptance still consume the question. No uncertain attempt is refunded. Clearing chat, rerunning, opening another session or restarting cannot reset the allowance. Missing/corrupt/unprovisioned storage fails closed. Changed demo ID/salt/signing key/end date fails the pinned DB binding; never replace the DB to restore allowances during the same demo.

Networks behind NAT share five questions. VPNs, changing networks and IPv6 address changes can yield a different address; IP limits do not establish a unique visitor or prevent determined abuse. Global lifetime caps protect against that exposure. Public access also requires resource/session admission controls; a financial demo is not a general production service.

## Proposed conservative configuration

- Seven-day demonstration, end timestamp explicitly approved; provisioning refuses more than 30 days.
- `OPENAI_MODEL=AI_ALLOWED_MODEL=gpt-5.6-luna` (existing model unchanged).
- `AI_DEMO_TOTAL_REQUESTS=20`, `AI_DEMO_TOTAL_TOKENS=500000`: lifetime across all IPs, no automatic month reset.
- Existing `AI_GLOBAL_MONTHLY_REQUESTS=20`, `AI_GLOBAL_MONTHLY_TOKENS=500000`: additional calendar-month ceilings.
- `AI_MAX_CONCURRENT_REQUESTS=1`. Up to five live browser sessions, two per TCP IP, subject to actual-host load verification.
- Existing 32,000 input-byte limit, 1,000 output-token limit, 1,000-character questions, six recent messages of 1,200 characters; SDK timeout 20 seconds, no retries, fixed endpoint/model allowlist, store=False.
- No automatic AI captions, upload calls or navigation calls. Explicit consent only.

Routing/explanation transport now omits explicitly labelled chart series and heavy scenario model matrices, compactly serialises JSON and strips raw/provenance identifiers from scenario evidence. Canonical calculations and complete deterministic execution context remain unchanged. This prevents a small normal portfolio from exceeding the original bound merely because of chart arrays/whitespace. Oversized evidence still refuses; no financial values are truncated to fit.

## Ordered launch steps after separate approval

1. Approve the exact GitHub release, hosting ceiling, seven-day duration, model and provider budget. Obtain operator SSH access and a DNS hostname without posting secrets in chat/GitHub. Do not use a mutable branch as an automatic deployment trigger.
2. Provision approved single server, SSH key access and firewall: HTTPS/HTTP public; SSH operator-only; app/signer ports 8501/8502 loopback and externally blocked. No unverified CDN or RealIP directives. Install NGINX with auth_request support and Python 3.12.10 pinned runtime lock. Create non-root service account, read-only release source and a private durable budget directory 0700.
3. Install examples in `deploy/`, replace domain/cert/runtime paths and issue trusted TLS certificate. Run `nginx -t`; verify HTTPS and WebSocket upgrade. Configure a writable private service-user cache/home location compatible with ProtectHome/ProtectSystem (not a public upload directory). Hard limits: app 3 GiB/200% CPU/128 tasks; signer 128 MiB/25% CPU/8 tasks; uploads/parser limits retained, proxy body 6 MiB, 5 r/s aggregate, 5 active WS global/2 per IP. Restrict/rotate logs and monitor memory, restarts and local health. Rate limiting HTTP does not throttle upgraded WebSocket messages.
4. Generate two different random 32-byte hex keys privately for signer and IP hashing. Approve concrete demo end epoch. Provision existing budget with `scripts/provision_ai_budget.py` then demo table with `scripts/provision_demo_quota.py`, using a temporary **offline provisioning environment**, without provider credentials or a public running process. After provisioning return runtime `AI_ACCESS_POLICY=disabled` until verification/activation approval. Never reprovision/reset on restart.
5. Stage a mocked-provider process on the actual host, **without an API key**, to verify: forged/duplicate/XFF-only assertions denied; injected headers replaced by NGINX; two source networks resolve to distinct quota hashes; direct origin/signer inaccessible; 5 accepted, 6th blocked across sessions/processes; restart preserves count; two provider calls charge one question; failures counted; global/concurrency caps hold. This stage must not invoke live SDK transport. A test DB/key is separate from the eventual demo DB; remove disposable fixture only after stopping test process. Local mocked ingress is not this host test.
6. Run dashboard/Discover/Trust/Exposure/scenario smoke with `examples/synthetic_ai_demo.csv` and required session isolation/invalid upload checks. Use live prices only if available; synthetic CSV quote values are assumptions and are not live market claims. Normal accepted equity for supplied quotes is $10,000, NVDA 85%, unrealised $1,850, realised unavailable. Check two normal concurrent sessions and the five-session ceiling once. Confirm health HTTP200 without exposing quota status or portfolio data. If host unstable lower limits or stop launch.
7. Configure dedicated provider project/private runtime key after approved budget; retain disabled policy. Inspect hard-limit settings and model/rate permissions. No paid calls until explicitly authorised. If approval includes one bounded live smoke question, it uses the same quota/global ledger and is counted; disclose its usage. Only then set public_demo and verify configuration before announcing live URL. If trustworthy ingress/storage cannot be established, keep paid AI disabled; quickest alternative is the deterministic demo or local/mock Copilot walkthrough.
8. Schedule end-of-demo paid shutdown and data deletion. The application blocks paid calls after the fixed end timestamp. Within seven days stop app/signer services, confirm no in-flight provider activity, remove the dedicated quota DB/journals and its two quota keys from host/secrets/backups, revoke dedicated provider key and delete any diagnostic exports containing hashes. No automatic per-IP reset; no secure-erasure claim. Do not retain quota backups beyond the deletion deadline. Retention is an operator obligation requiring a verified scheduled task before launch, not a local test result.

## Release / rollback

Merge-commit integration preserves PRs #1–#11. New demo changes require reviewed validation before deployment; no financial engine changes. Pin the final release SHA and archive checksum. Keep the previous known-safe AI-disabled artifact/config. Emergency stop: set disabled, restart the app to terminate active sessions, revoke project key if necessary. Rollback source/config while keeping the **latest authoritative** quota DB. Never restore an older ledger while AI is enabled. A first release with no safe previous artifact goes offline. Session-local portfolios/reviews/constituents/chat can be lost on restart; visible warning retained.

Host prerequisites still unverified: actual TLS, proxy identity replacement, durable volume permissions/restarts, capacity, secret injection, provider account restrictions, spending controls, public market reliability, deletion schedule and live URL. Do not claim public AI ready until those pass.
